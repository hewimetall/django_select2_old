# django-select2-old

Legacy `django-select2` widgets, fields, views, and template tags updated to run on
modern Python and Django.

## Setup

Create and activate a virtual environment, then install the package:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

For development and security auditing tools:

```bash
python -m pip install -e ".[dev]"
```

For multi-process auto-field support backed by memcache:

```bash
python -m pip install -e ".[memcache]"
```

## Django configuration

Add the application and URL route to a Django project:

```python
INSTALLED_APPS = [
    # ...
    "django_select2",
]
```

```python
from django.urls import include, path

urlpatterns = [
    # ...
    path("select2/", include("django_select2.urls")),
]
```

The package serves static assets from `django_select2/static/`. In production,
run Django's normal static collection command from the host project:

```bash
python manage.py collectstatic
```

## Runtime settings and environment

Configuration is read from Django settings when the package is imported:

| Setting | Default | Purpose |
| --- | --- | --- |
| `AUTO_RENDER_SELECT2_STATICS` | `True` | Include Select2 JavaScript and CSS through widget media. |
| `SELECT2_BOOTSTRAP` | `False` | Use bundled Bootstrap-compatible Select2 CSS. |
| `GENERATE_RANDOM_SELECT2_ID` | `False` | Generate random auto-field IDs instead of deterministic IDs. |
| `ENABLE_SELECT2_MULTI_PROCESS_SUPPORT` | `False` | Store auto-field IDs in the database and optional memcache for multi-process deployments. |
| `SELECT2_MEMCACHE_HOST` | `None` | Memcache host for multi-process support. |
| `SELECT2_MEMCACHE_PORT` | `None` | Memcache port for multi-process support. |
| `SELECT2_MEMCACHE_TTL` | `900` | Memcache entry lifetime in seconds. |

`SECRET_KEY` is used as salt for deterministic auto-field IDs.
Projects using `django.contrib.staticfiles` must also configure Django's
standard `STATIC_URL` setting.

## Run

This repository is a reusable Django app, not a standalone server. To run it,
install it into a Django project, include `django_select2.urls`, and start that
project's development server:

```bash
python manage.py runserver
```

## Test

Install development dependencies and run the test suite:

```bash
python -m pip install -e ".[dev]"
pytest
```

The default pytest configuration enforces real coverage of at least 93% for the
`django_select2` package:

```bash
pytest --cov=django_select2 --cov-report=term-missing --cov-fail-under=93
```

## Dependency audit

Audit declared Python dependencies with:

```bash
python -m pip_audit
```

If a requirements file is generated by a deployment workflow, audit that exact
file with:

```bash
python -m pip_audit -r requirements.txt
```
